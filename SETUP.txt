================================================================================
 SETUP GUIDE — Artistic Social Media Marketing (React + Vite + Tailwind CSS)
================================================================================

This project was delivered to you as ready-to-use SOURCE FILES (no
node_modules, no lockfile-installed packages). Follow the steps below to get
it running. Takes about 2 minutes.

--------------------------------------------------------------------------------
0. PREREQUISITES
--------------------------------------------------------------------------------
- Node.js 20.19+ or 22.12+ (Vite 8 / Tailwind 4 requirement)
- npm 10+ (comes with Node)

Check your version:
    node -v
    npm -v

--------------------------------------------------------------------------------
1. IF YOU'RE STARTING FROM THE PROVIDED FILES (recommended)
--------------------------------------------------------------------------------
You already have a full Vite project structure (vite.config.js, index.html,
src/, public/, package.json). Just install dependencies and run it:

    cd artistic-social-media-marketing
    npm install
    npm run dev

Open the URL Vite prints (usually http://localhost:5173).

That's it — skip to step 4 (Tailwind is already wired up, see step 3 to
understand how).

--------------------------------------------------------------------------------
2. IF YOU WANT TO RECREATE THE PROJECT FROM SCRATCH
   (e.g. to merge these files into a different base project)
--------------------------------------------------------------------------------
    npm create vite@latest my-app -- --template react
    cd my-app
    npm install

Then copy this project's `src/`, `public/`, `index.html` and `vite.config.js`
over the freshly scaffolded ones (or merge by hand), and continue with step 3.

--------------------------------------------------------------------------------
3. INSTALLING DEPENDENCIES (already in package.json, run once)
--------------------------------------------------------------------------------
Runtime dependencies:
    npm install react-router-dom swiper gsap yet-another-react-lightbox \
                 animate.css @fortawesome/fontawesome-free

Tailwind CSS v4 + the official Vite plugin (dev dependency):
    npm install -D tailwindcss @tailwindcss/vite

--------------------------------------------------------------------------------
3a. HOW TAILWIND IS CONFIGURED (already done in this project — reference only)
--------------------------------------------------------------------------------
Tailwind v4 does not need a tailwind.config.js for this project. It's wired
up two places:

  1. vite.config.js — the Tailwind Vite plugin is registered:

        import tailwindcss from '@tailwindcss/vite'
        export default defineConfig({
          plugins: [react(), tailwindcss()],
        })

  2. src/index.css — Tailwind is imported and every design token from the
     original theme (colors, font, custom keyframes) is declared in an
     `@theme { ... }` block, e.g.:

        @import "tailwindcss";
        @theme {
          --color-accent: #bff747;
          --color-dark: #000000;
          ...
        }

     This makes utilities like `bg-accent`, `text-primary`, `border-divider`
     available everywhere, matching the original :root CSS variables.

If you ever DO want a tailwind.config.js (e.g. to add plugins like
@tailwindcss/typography), you can still create one — v4 will auto-detect it
alongside the CSS-based config.

--------------------------------------------------------------------------------
4. RUNNING THE APP
--------------------------------------------------------------------------------
Development server (hot reload):
    npm run dev

Production build:
    npm run build
    → outputs to dist/

Preview the production build locally:
    npm run preview

Lint:
    npm run lint

--------------------------------------------------------------------------------
5. ADDING THE HERO BACKGROUND VIDEO (optional)
--------------------------------------------------------------------------------
The original theme streams its hero background video from the template
author's demo server. That external dependency was intentionally NOT hard-
coded here. To use your own video:

    1. Drop an .mp4 file into  public/videos/hero-bg-video.mp4
    2. That's the exact path already referenced in
       src/components/sections/home/Hero.jsx — no code changes needed.

Until you add one, the <video> element simply shows nothing and the poster
image (/images/hero-bg.jpg) / dark overlay is what's visible, which still
looks correct.

--------------------------------------------------------------------------------
6. RUNNING TESTS
--------------------------------------------------------------------------------
Unit / component tests (Vitest + React Testing Library) — no extra setup
needed, these run entirely in a simulated DOM (jsdom):

    npm test              # run once
    npm run test:watch    # watch mode while developing

22 tests covering Button, AccordionItem, Pagination, Counter (the
counter-up animation), the Contact form's validation, the mobile menu's
open/close + submenu accordion, and the project category filter (the
Isotope replacement). Note: the two Counter animation tests wait on a real
2-second requestAnimationFrame loop rather than mocked timers, so under
heavy system load they can occasionally need a retry — everything else is
deterministic.

End-to-end tests (Playwright) — these drive a real browser against the
production build, so they need Playwright's browser binaries downloaded
once first:

    npx playwright install        # one-time, downloads Chromium + WebKit
    npm run test:e2e

This builds the app, serves it on port 4173, and runs 44 tests (22 per
browser: Chromium desktop + Mobile Safari viewport) covering: every page
renders, detail pages resolve by slug, unknown routes fall back to 404, the
mobile menu opens/expands/navigates, the contact form validates and
submits, the project filter narrows results, and the image/video gallery
lightboxes open. NOTE: `npx playwright install` requires network access to
download browser binaries — it could not be run in the environment this
project was built in, so treat the e2e suite as written-but-unverified
until you run it once locally; the unit test suite above was fully run and
passes.

--------------------------------------------------------------------------------
7. PROJECT STATUS
--------------------------------------------------------------------------------
Complete. All 17 pages from the original theme are converted: Home, About,
Services, Service Details, Team, Team Details, Pricing, Testimonials, FAQs,
Blog, Blog Details, Projects, Project Details, Image Gallery, Video Gallery,
Contact, 404. See README.md for the folder structure, the original-plugin-to

========================== Header Section =======================================

----------------- useStickyHeader.js --------------

/**
 * Reproduces the original scroll behaviour from js/function.js + the
 * `.hide` / `.active` rules in custom.css:
 *   - scrollY <= 150   -> header sits in normal flow, over the hero
 *   - 150 < scrollY <= 600 -> header slides up out of view
 *   - scrollY > 600    -> header re-appears, pinned + blurred background
 *
 * (In the original CSS both `.hide` and `.active` can be applied at once;
 * `.active` wins because it's declared later. We reproduce that resolved
 * end-state directly instead of relying on class order.)
 */

----------------- CustomCursor.jsx ---------------

/**
 * Replacement for js/magiccursor.js: a small accent dot that follows the
 * mouse exactly, plus a larger ring that eases toward it. Automatically
 * disables itself on touch/coarse-pointer devices.
 */

============================== Hero Section =================================

------------------------ useReveal.js -----------------

/**
 * Lightweight replacement for WOW.js. Original markup used
 * `class="wow fadeInUp" data-wow-delay="0.2s"`; here a component does:
 *
 *   const { ref, revealed } = useReveal();
 *   <div ref={ref} className={`reveal-up ${revealed ? "is-revealed" : ""}`}>
 *
 * `delay` (seconds) mirrors data-wow-delay for staggered groups.
 */

------------------- Reveal.jsx --------------------

/**
 * Drop-in wrapper replacing `class="wow fadeInUp" data-wow-delay="0.2s"`.
 * Usage: <Reveal variant="up" delay={0.2}><Card /></Reveal>
 */

------------------ splitText.js -----------------

/**
 * Splits a plain string into an array of words, each word being an array
 * of single characters. Used by <AnimatedText /> to build the per-word /
 * per-character <span> markup that GSAP then staggers in — a dependency
 * -free stand-in for GSAP's SplitText plugin.
 *
 * NOTE: only pass plain text as children (no nested elements/markup).
 */

------------------- AnimatedText ----------------

/**
 * Replaces the original `.text-anime-style-1` / `.text-anime-style-2`
 * GSAP + SplitText treatment used on the hero and section headings.
 *
 * Props:
 *  - as         tag to render (h1, h2, h3, span...) — default h2
 *  - variant    "words" (style-1) or "chars" (style-2)
 *  - text       plain leading text
 *  - accent     optional trailing text rendered in the accent color
 *               (mirrors `<span>accent text</span>` in the source markup)
 */

Elevate your online presence, engage your audience, and meaningful results with tailored social media strategies.
